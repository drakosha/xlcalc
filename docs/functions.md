Status: 43,778 cases are checked against Excel, with Excel's results stored in this repository. In en-US they are the coverage run (5,275), the case sets (25,898), the probes (959) and the random check (4,000). In ru-RU they are the coverage run (5,275) and the case sets (2,371): the locale sets and six en-US sets run again in ru-RU. Spilling is checked on 104 more workbooks (`docs/spill.md`), displayed text on 13,351 cells, 10,020 in en-US and 3,331 in ru-RU (`docs/formats.md`), structure operations on 317 workbooks (`docs/structure.md`), tables on 176 workbooks in en-US and ru-RU (`docs/tables.md`), hidden rows, the 1904 date system and iterative calculation on 98 workbooks, and circular references without iterative calculation on 27 workbooks in Excel for Windows, 6 of them predicted before they ran (`bench/coverage/workbook/`, `docs/cycles.md`), data validation and outlines on 74 workbooks in both versions of Excel (`docs/validation.md`), and hidden sheets on 50 workbooks in both versions of Excel (`docs/xlsx.md`).

Every function in the list matches Excel en-US on all of its cases in the coverage run (`docs/coverage-formulajs.md`) and in the Excel case sets (`test/excel/cases/`), which also cover the functions formula.js lacks (`XLOOKUP`, `XMATCH`, `TEXTBEFORE`, `ADDRESS` and others), with two kinds of exceptions, both listed in `test/excel-cases.ts`. `XIRR` matches within 1e-6 relative (`SOFT`: Excel stops its iteration within 1e-8 of the root, while the engine finds the root), and so do the t and F quantiles (`T.INV`, `T.INV.2T`, `TINV`, `F.INV`, `F.INV.RT`, `FINV`), where Excel loses up to 7 digits at 10^9 degrees of freedom and more; and a few cases differ knowingly (`KNOWN`: the engine's result is pinned by the tests and the reason is given in [Known differences](limitations.md)). A difference the random check finds outside the functions (operators, the array layer) is pinned as open in `test/excel-open.ts` until it is fixed (none is open now). `TODAY`, `NOW`, `RAND` and `RANDBETWEEN` (volatile) have their own semantics and clock tests instead; `RANDARRAY` has Excel cases for what does not depend on the random draw (sizes, bounds, whole numbers) and clock tests.

How acceptance works: the coverage run generated 5,275 cases for 402 Excel functions, typical calls (mostly the examples from Excel's function reference) and edge cases, and calculated them in Excel 16.113 for Mac with the en-US locale and English UI, as dynamic array formulas the way Excel 365 saves them (no implicit intersection, and an array result spills); the results are stored in `test/excel/coverage/excel-en.json`. `test/excel.test.ts` calculates the cases of every whitelisted function with this engine, in one workbook with the coverage run's data sheet, and compares them: numbers within |a−b| ≤ 1e-9·max(1,|a|), and text, booleans and error codes exactly. The test needs neither Excel nor LibreOffice. Rules that do not belong to a single function (numbers as text, long number literals, criteria over entire columns) are checked the same way against Excel's results for 959 probes in `test/excel/probes.json` (`test/excel-probes.test.ts`). Every case set and the probes are also calculated as dynamic array formulas. The `core` set pins the rules of operators, arrays and references the random check pointed to, and `near-integer` how Excel reads a number close to a whole number, on exact values from one unit in the last place to 10^-6 away. The random check (`fuzz`) generates formulas over the whitelist from a seed, with nested calls, operators, ranges and arrays, number and date text, and errors among the arguments, and compares them with Excel's results the same way; the rules it found are pinned by `fuzz-rules`, and the differences it found outside the functions are listed in `test/excel-open.ts`. Arrays are checked by the `arrays` set: operators and constants, array results, aggregates and lookups over arrays, every whitelisted function's single-value arguments given a range and an array, and the functions that return arrays. The older cases in `test/semantics-cases.ts` (expected results from Excel's documentation, cross-checked with LibreOffice) still run too.

Notes on semantics:

- Arguments are coerced by kind, the same way for every function in a group. Numeric arguments parse text as `VALUE` does (`"$1,000"`, `"50%"`, `"1 1/2"`, and date and time text: `ABS("2025-01-31")` is 45688) and accept booleans, and so do operators and `TEXT`. A range in `SUM`, `AVERAGE`, `MAX` and similar functions contributes only its numbers, while a direct argument is coerced. Date arguments parse date text as Excel does in the workbook's locale (en-US: `2025-01-31`, `1/31/2025`, `31-Jan-2025`; `1/31` and `Jan 31` in the clock's year), and date and time text after a space is not a date or time there (`DAY(" 1/31/2025")` is `#VALUE!`, while `VALUE`, `DATEVALUE`, `TIMEVALUE` and `DAYS` drop the spaces). `"TRUE"`/`"FALSE"` text (`"ИСТИНА"`/`"ЛОЖЬ"` in ru-RU) is a boolean where a boolean is expected; `AND`, `OR` and `XOR` accept it given directly too, and skip other text.
- Where several arguments are invalid, the error is the one Excel finds first: arguments given as values are read before references and arrays (`LARGE(A1:A9,"x")` is `#VALUE!` even with an error in A1:A9; `AND`, `CONCAT` and `TEXTJOIN` return an error given as a value before one inside a range). The exceptions: `GCD`, `LCM` and `MULTINOMIAL` read every argument in order, including values inside ranges and arrays, and check signs last; `XIRR` finds a boolean or other text among its dates before a blank date; the former Analysis ToolPak functions check in the order Excel reads: the discount and most bond functions read the basis first, the coupon functions check the dates, the frequency and the basis in turn, the radix functions read their places first, `DELTA` and `GESTEP` their second number, and `COMPLEX` its suffix. Functions over two arrays (the paired statistics, `SUMX2MY2` and related functions, `CHISQ.TEST`, `T.TEST`) take a reference to a single cell first, argument by argument, returning its error and treating a blank cell as `#VALUE!` (an array of one element is an array), then compare sizes (`#N/A`), then look for errors inside; `SUMPRODUCT` takes each array's error, and a blank cell given alone, before comparing their shapes (`#VALUE!`).
- `LINEST`, `LOGEST`, `TREND` and `GROWTH` drop a variable that depends linearly on the others or on the constant, giving it a coefficient and standard error of 0, as Excel does (Excel selects variables by their largest remaining norm; with one y value, a row of x serves as its variables). Sizes are checked before values (`#REF!` before `#VALUE!`), and an error among the new x values of `TREND` or `GROWTH` is `#VALUE!`. With a constant, they center y and each variable on their means before the decomposition, so data far from 0 relative to their spread keep their digits (`LINEST` of 1E12, 1E12 + 0.01, 1E12 + 0.02 on 0, 1, 2 returns the slope of the stored values, 0.010009765625, as `SLOPE` does); `TREND` and `GROWTH` evaluate b + m·x from the coefficients, as Excel does.
- The complex-number functions parse each part of complex text as `VALUE` parses a number in the workbook's locale, the first part with its own sign (`IMREAL("50%+i")` is 0.5, `IMREAL("-(1)+i")` is 1, and `IMREAL("1 000+2i")` is `#NUM!` in en-US), and a real number from text as `VALUE` does when no sign follows its first character (`IMABS("50%")` is 0.5, `IMREAL("1/2/2025")` is 45659, and `IMREAL("2025-01-31")` is `#NUM!`), as Excel does.
- Criteria (`SUMIF`, `SUMIFS`, `COUNTIFS`) compare text case-insensitively but accent-sensitively and support `*` and `?` (where `~` takes the next character literally; text without `*` or `?` is compared as is, `~` included). They parse numbers, dates and times inside criterion text as `VALUE` does (`">=1/1/2026"`, `"$1,000"`, `"50%"`), and a number criterion's `=` also matches text that parses as that number (`2` matches `"2"`, `0.5` matches `"50%"`) while its `<>` matches all text, as in Excel. An error, or its text in any case (`"#N/A"`), matches the cells containing that error; `<` and `>` order errors as `ERROR.TYPE` does. A criterion's own text does not parse `€` (`COUNTIF(A1:A3,"€100")` looks for that text), while a number criterion's `=` treats a cell's `€100` as 100, as in Excel. A criterion with nothing after its operator distinguishes blank cells from a formula's empty text as Excel does: `""` (or a reference to a blank cell concatenated with nothing) matches both, `"="` matches only blank cells, and `"<>"` matches every cell that is not blank, empty text included (`COUNTIF(A1:A3,"<>")` is 1 when A1 contains `=""` and A2:A3 are blank). Their ranges must have the same referenced size (otherwise `#VALUE!`); entire columns on sheets with different numbers of rows are compatible, and blank cells of an entire column count when every criterion matches a blank (`COUNTIFS(A:A,"")`).
- Numbers are converted to text (`&`, `CONCAT`, text arguments) as in Excel: rounded to 15 significant digits, in positional notation when that takes at most 20 characters, not counting the sign (`0.0000000745`, `10000000000000000000`), and otherwise in scientific notation with an exponent of at least two digits (`7.4500104300146E-06`, `1E+20`). `TEXT` with the `General` format follows Excel's other rule, at most 11 characters (`0.333333333`, `1.23457E-05`).
- Number literals and numeric text keep 15 significant digits and drop the rest, as Excel reads them (`123456789012345678` is 123456789012345000); numeric text of 1E+308 or more is not a number (`"1e308"+0` is `#VALUE!`), since Excel's largest number is below it; a result smaller than the smallest normal number (2.2250738585072E-308) is 0.
- When a formula's last operation outside parentheses is `+` or `-`, its result is 0 if it is smaller than eight units in the last place of its left operand, that is, 2^(e-49) for a left operand between 2^e and 2^(e+1), as Excel treats such a result as the error of decimal operands in binary: `=0.1+0.2-0.3`, `=0.5-0.4-0.1` and `=1E+15+0.3-1E+15` are 0 (the last is 0.25 in doubles), while `=(0.1+0.2-0.3)`, `=1*(0.1+0.2-0.3)`, `=0.1+0.2-0.3+0`, `=-(0.1+0.2-0.3)`, a function argument and `LET`'s calculation keep 5.55E-17; over an array, each element likewise. `SUM` applies the rule at its last addition (`SUM(0.1,0.2,-0.3)` is 0, `SUM(0.1,0.2,-0.3,1E-20)` is 5.55E-17 + 1E-20), and so do `SUBTOTAL`, `AGGREGATE` and `AVERAGE`, whose mean is 0 where that addition becomes 0 (a sum that plain addition leaves at 0, as `1E16`, `1` and `-1E16` produce, keeps its stable mean: not verified); `SUMIF`, `SUMIFS`, `SUMPRODUCT`, `MMULT` and `NPV` keep the double. Excel for Windows returns the same. A defined name's formula, conditional formats and data validation were not verified: the engine applies the rule in a rule's formula as in a cell's, but not in a name's.
- A negative number raised to a fractional power (`^`, `POWER`) is its real root where 1/y, to 15 significant digits, is an odd whole number below 2^31 - 1, calculated as Excel calculates it, -exp(y·ln(-x)): `(-32)^0.2` is -2, `(-8)^(1/3)` is -2 to 15 digits and -1.9999999999999998 internally, as in Excel, and `(-8)^0.333333333333333` is a root too; `(-8)^(2/3)`, `(-8)^0.33333333333333` and `(-2)^(1/2147483647)` are `#NUM!`. Excel for Windows returns the same, except for the last digit of some roots.
- An operator converts its left operand before looking at the right one: `"abc"-NA()` is `#VALUE!`, and `NA()-"abc"` is `#N/A`; over arrays, each element the same way, and a position outside a shorter array is `#N/A` whatever the other operand contains.
- Numbers compare as in Excel: `=`, `<` and the other comparison operators and criteria (`COUNTIF`, `SUMIFS` and the rest) treat numbers equal to 15 significant digits as equal (`0.1+0.2=0.3` is TRUE), while lookups, `MATCH`, `XMATCH`, `UNIQUE`, `RANK`, `DELTA` and sorting compare exactly; `INT`, `TRUNC`, `ROUND`, `ROUNDDOWN` and `ROUNDUP` read their number to 15 significant digits (`INT(1-2^-52)` is 1, and so is `INT(FTEST(A1:A8,A1:A8))`; `ROUND(1.05*(0.0284+0.0046)-0.0284,4)` is 0.0063). `FLOOR` of 0 with a significance of 0 is 0, and of any other number `#DIV/0!`, and the mode argument of `FLOOR.MATH` and `CEILING.MATH` reverses the rounding of negative numbers whenever it is not 0 (`FLOOR.MATH(-7.1,1,0.01)` is -7).
- A whole-number argument less than 2^-22 (about 2.4·10^-7) short of an integer is treated as that integer (`LEFT("abc",0.9999999)` is `"a"`) in `LEFT`, `RIGHT`, `FIND`, `SEARCH`, `REPLACE`, `SUBSTITUTE`, `TEXTBEFORE`, `TEXTAFTER` (the instance), `FIXED`, `DOLLAR`, `ROUND` (the digits), `INDEX`, `ADDRESS`, `DATE`, `WEEKDAY` (the type), `FACT`, the column index of `VLOOKUP` and `HLOOKUP`, the field of the database functions, the function number of `SUBTOTAL` and `AGGREGATE`, the tails and type of `T.TEST` and the tails of `TDIST`, the month of `DB` and the format of `ARRAYTOTEXT` and `VALUETOTEXT`; other whole-number arguments are truncated, as Excel truncates them (`MID`, `REPT`, `CHOOSE`, the digits of `ROUNDDOWN`, `ROUNDUP` and `TRUNC`, the counts of the statistical functions, the months of `EDATE`, and the rest of what the `near-integer` set verified). `ISEVEN` and `ISODD` treat a number less than 10^-10 short of an integer as that integer, `DATE` rounds a day below zero down, and `DAY`, `MONTH`, `YEAR`, `WEEKDAY`, `HOUR`, `MINUTE`, `SECOND` and a format's whole seconds read a date and time to the second as Excel does: half a second is added and the sum is split into days and seconds in floating point, so 0.4 s before midnight is the next day, an exact half second at a present-day date stays below (`SECOND(45688+1/256)`, 37.5 s, is 37) while one at less than a day rounds up (`SECOND(10.5/86400)` is 11), and a moment that rounds past 9999-12-31 is `#NUM!`.
- Argument counts are those Excel accepts when loading: `SORTBY` takes each additional by-array with its order (2, 3, 5… arguments; Excel rejects a workbook with `SORTBY` of 4 arguments), `SWITCH` takes at most 126 pairs and a default, a function newer than Excel 2007 (`CONCAT`, `TEXTJOIN`, `STDEV.S`, `XOR`, `HSTACK`, `AGGREGATE` and the others stored with the `_xlfn.` prefix) takes at most 254 arguments (253 for `SORTBY`, `MAXIFS` and `MINIFS`), and the others 255; any other count has the error code `syntax`.
- `IF`, `IFERROR`, `IFNA` and `SWITCH` do not evaluate the branch that is not taken, unless their condition (a value, an expression or a value to match) is an array: then every argument is evaluated and the function works element-wise.
- An argument omitted between commas (`IF(A1,,1)`, `SUM(1,,2)`) is treated as Excel 16.113 treats it, as verified on every whitelisted function's arguments (the `omit` sets): as a blank, read by the argument's kind as 0, `""` or FALSE (`ROUND(1.5,)` is 2, `LEFT("abc",)` is `""`, `VLOOKUP(4,A1:C6,2,)` is an exact match, `IF(TRUE,)&"x"` is `"x"`, `COUNT(1,,2)` is 3); as `#VALUE!` where the function expects an array or a reference (`CORREL(,A1:A8)`, `INDEX(,1)`); as not given, with the function's default, where the function treats it that way (the optional arguments of newer functions: `SEQUENCE(3,,5)`, `XLOOKUP(4,A1:A6,B1:B6,)` is `#N/A`; the decimals of `FIXED`, the style of `ADDRESS`, the significance of `CEILING.MATH` and related functions, the values of `PRODUCT`; an omitted ignore_empty of `TEXTJOIN` is TRUE); and in the former Analysis ToolPak functions as not given, a required one as `#N/A` (`EDATE(,1)`, `ERF(1,)`). A formula that omits a reference Excel requires (a criteria range, the list of `RANK`, the references of `SUBTOTAL`) has the error code `syntax`, since Excel does not load it. The table of functions that differ from the blank rule is `src/functions/omitted.ts`.
- `LET` binds names to values, each visible from the end of its value to the end of its `LET` and case-insensitively, with an inner `LET` shadowing an outer one and both shadowing a defined name with the same name; a name used in its own value or after its `LET` refers to a defined name (`LET(x,x+1,x)` is `#NAME?` without one). A value is evaluated once, on its first use (`LET(x,RAND(),x-x)` is 0; an error in an unused value does not count), and a reference stays a reference (`LET(r,A1:A9,SUM(r))` skips text, and `SUMIF(LET(r,A1:A9,r),">0")` works); an omitted value is a blank. Excel loads a `LET` that ends with a value, which makes an even number of arguments (`LET(x,1,y,2)` returns 2), and one with at most 254 arguments, but not one that declares a name twice or uses a word that cannot be a name (`LET(A1,1,A1)`: the error code `syntax`). The canonical text spells every use as its name is declared (`LET(Abc,1,ABC+1)` becomes `LET(Abc,1,Abc+1)`), as Excel shows it; in ru-RU `LET` keeps its English name.
- Arrays follow Excel 365's dynamic arrays. An operator, or a function argument that expects a single value, given an array or a range of several cells works element-wise: the result has the larger number of rows and of columns, a single row or column is repeated, a position outside a shorter array is `#N/A` (`{1,2,3}+{1,2}` is `{2,4,#N/A}`), and a function evaluates it as `#N/A` when it reaches that argument (`IFERROR({1;2;3},{7;8})` is `{1;2;3}`). The former Analysis ToolPak functions (`EOMONTH`, `BESSELJ`, the radix and complex-number functions, the bond functions and others) and the field argument of the database functions do not accept a range there: `#VALUE!`, while an array (`EOMONTH(A1:A2+0,0)`) works; `N` and `T` take the top-left cell of a range. Functions that accept ranges accept arrays the same way (`SUM` adds an array's numbers), except that `MAXA`, `STDEVA` and related functions take only an array's numbers and `AVERAGEA` counts its text as 0. An array with one value stays an array under an operator or a lifted call (`TYPE({1}+0)` is 64, so `SUM({TRUE}=TRUE)` skips the boolean and is 0), while a one-cell reference is a value (`TYPE(A1:A1+0)` is 1). An entire column is an array of 1,048,576 rows (`SUM(B:B+1)` adds 1,048,576), calculated on its occupied rows.
- `INDEX`, `TAKE`, `DROP`, `XLOOKUP` (including its `if_not_found`), `CHOOSE`, `IF`, `IFS` and `SWITCH` return references when given references, even for a single cell, so `SUMIF(INDEX(A1:C9,0,1),">2")` works and `SUM` skips text there (`SUM(IF(TRUE,A2))` is 0 when A2 contains the text "2"); `IFERROR`, `IFNA`, `FILTER`'s `if_empty` and unary `+` return values. `HSTACK` and `VSTACK` return an error given as a value (`VSTACK(1,1/0)` is `#DIV/0!`) but stack a reference to a cell containing an error; the other functions that return arrays return arrays, where a blank cell is an empty value (`COUNTA` counts it, and `ISBLANK` is TRUE). `TYPE` of an array, or of a range of several cells, is 64. `IFS` returns the `#VALUE!` of a text condition as an array of that one error, so `ROWS(IFS("x",1,TRUE,2))` is 1, as in Excel, while an error given as a condition is the result itself (`ROWS(IFS(1/0,1))` is `#DIV/0!`).
- Sorting (`SORT`, `SORTBY`) is stable and orders numbers, text, booleans, errors by the number `ERROR.TYPE` returns (`#DIV/0!` before `#N/A`), then blanks (blanks last in a descending sort too); text compares as `<` does. `SORTBY` with an array or a range of several cells as a sort order returns what Excel returns: an array as large as the sort orders, lifted as an operator lifts them (an order of one row or column repeats, and positions beyond a shorter one get `#N/A`). At each position, in row order, it returns the error of the call with the orders at that position (an error given as an argument, or `#VALUE!` for an order that is not 1 or −1 or is empty, or for a by-array of a different size), the first value of the first call that sorts, and after it blanks, or `#VALUE!` when it has more than one by-array (`SORTBY(A1:A6,B1:B6,{1;-1})` is the first value and a blank, and `SORTBY(A1:A6,B1:B6,{2;-1})` is `#VALUE!` and the first value of the descending sort). A by-array with one value counts as one row and one column: the first by-array decides whether rows or columns are sorted and every later one must match it, so a single value fits an array of one column or one row (`SORTBY(A1:A6,5)` keeps the order), while next to a by-array that covers the array's rows it is `#VALUE!` (`SORTBY(A1:A6,B1:B6,1,5,1)`).
- `SUBTOTAL` and `AGGREGATE` (options 0–3) skip the cells whose formula calls either of them anywhere (including `=SUBTOTAL(9,A1:A2)*10`, but not a plain reference to such a cell), so nothing is counted twice. `SUBTOTAL` 101–111 and `AGGREGATE` options 1, 3, 5 and 7 skip hidden rows, and `SUBTOTAL` 1–11 skips the hidden rows of a filtered sheet ([Hidden rows and filters](formulas.md#hidden-rows-and-filters)). `AGGREGATE` 14–19 accept an array as well as a reference (`AGGREGATE(14,6,10/A1:A9,1)`).
- `INDEX` of an array of several rows and columns with only a row number returns that row (`INDEX({1,2,3;4,5,6},2)` is `{4,5,6}`), and of such a range `#REF!`; `FILTER` returns its if_empty as a value, a reference by its values (`ISREF` of it is FALSE).
- Lookups compare within a type (numbers, text, booleans), text case-insensitively, and never match blanks or errors in the data. An exact match in `VLOOKUP`, `HLOOKUP` and `MATCH` (and `XLOOKUP`, `XMATCH` in match mode 2) supports `*`, `?` and `~`, where `~` escapes any character. An approximate match is Excel's binary search over the referenced cells, so it returns Excel's result on unsorted, mixed and entire-column data too (checked on about 200 such cases); `MATCH` with type −1 scans. `XLOOKUP` and `XMATCH` take the next smaller or larger value (match modes −1 and 1) across types, numbers < text < booleans (`XLOOKUP(10,A1:A3,B1:B3,,1)` over 2, TRUE and `"ala"` finds `"ala"`), and their search modes 2 and −2 are Excel's binary search: it compares at the middle of the remaining positions, both ends included, treats a blank or an error as greater than any key, and runs over every position of the reference, including past its last value, so on unsorted data and over blanks it returns what Excel returns (`XLOOKUP(5,A1:A6,B1:B6,,0,2)` over 1, 2, a blank, 4, 5, 6 is `#N/A`); an equal value is the first of its run (with −2 the last), and wildcards there are `#VALUE!`. Match mode 3 finds a regular expression anywhere in a value's text (numbers by their text, a blank as empty text, case-sensitive unless the pattern starts with `(?i)`), as Excel for Mac does (`XMATCH("[A-Z][a-z]+y",A2:A9,3)`); with a binary search it is `#VALUE!`. Patterns are read in JavaScript's syntax with PCRE2's commonest constructs, or in Excel's with a level of `xlcalc/regex` ([Regular expressions](regex.md)). A blank lookup value is 0 in `VLOOKUP`, `HLOOKUP`, `MATCH` and `LOOKUP`, and finds a blank cell in `XLOOKUP` and `XMATCH`.
- `LOOKUP` continues reading beyond the end of a result reference shorter than its lookup array, as Excel does, whatever returns the reference (a spill, `IF`, `INDEX`, `TAKE`): down a column, or to the right of a row or a single cell (`LOOKUP(4.19,L1:L6,B2:B3)` and `LOOKUP(4.19,L1:L6,IF(TRUE,B2:B3))` return B4, and `LOOKUP(4.19,L1:L6,B2)` returns D2, when 4.19 falls between L3 and L4), and a blank beyond the end of the sheet. The cells it may read count among the formula's references: below a column, and to the right of a row or a cell, as far as the lookup array is long (in both directions for a part of a rectangle that `INDEX` or `TAKE` may return), and beyond a spill in its array's direction.
- An error in a column index or match type taken from a cell is `#REF!`, as in Excel. An array or a range of several cells as the column (row) index of `VLOOKUP` (`HLOOKUP`) returns the found row (column) at each number, shaped like the index; the first number in order that is not valid determines the result for all: `#VALUE!` below 1, `#REF!` beyond the table, for an error, or for text that is not a number. A call lifted by an array lookup value or match mode reads the index's top-left number in each call (`INDEX(VLOOKUP({5;8},D!L1:N6,{2;4},FALSE),2)` is `"eight"`). A range as the match type of `MATCH` gives its top-left cell. A lookup table of `VLOOKUP`, `HLOOKUP` or `MATCH` given as a single value is read as a number and finds nothing (`MATCH(5,5,0)` is `#N/A`, `MATCH(5,"x",0)` `#VALUE!`); a single value as the lookup array of `XLOOKUP` looks along the return array's single row, otherwise its single column (`XLOOKUP(0,0,A1:A6)` is A1:A6).
- Database functions (`DSUM` and the rest) read records by rows under a header row, with a field or a criteria header naming the first column whose header matches it case-insensitively (the text `true` names a header TRUE); a database without records is `#VALUE!`, and so is a field taken from a cell containing an error (an error given as the field is itself the result). Criteria are written as in `SUMIFS`, except that text without an operator matches the values that start with it (`App` selects `Apple`); criteria rows are alternatives, and the conditions in a row must all be true. A condition under a header that is not a field name is true for every record when it is `TRUE` (Excel's computed criterion) and for none otherwise.
- `TEXTBEFORE` and `TEXTAFTER` round a fractional instance down (`-1.2` becomes -2) and return `#VALUE!` for an instance beyond the text's length, or for delimiters that are all longer than the text when an instance is given (`TEXTAFTER("del","deli",1)`; `TEXTAFTER("del","deli")` is `#N/A`), whatever `if_not_found` says; `TEXTSPLIT` with neither a column nor a row delimiter is `#VALUE!`.
- Text longer than 32,767 characters: `&` and `CONCATENATE` truncate it there, `CONCAT` and `TEXTJOIN` return `#CALC!`, and the other text functions `#VALUE!`, as Excel does. An empty array (a `FILTER` that keeps nothing, `TAKE` of zero rows, `DROP` of everything) is `#CALC!` too.
- `VALUE` parses currency (`$` before the number, `€` before or after it: `12€` is 12; no other symbol, so `£100` is `#VALUE!`), thousands separators, parentheses, `%`, exponents, `1 1/2` (and `$1 1/2` and `(1 1/2€)`), and dates and times as Excel en-US does, including times beyond 24 hours (`25:00`), and date text without a year in the clock's year (`1/31`; `2/29` in a year that is not a leap year is February 2029, as in Excel); time text follows the same rule in `VALUE`, operators and date arguments (`6 PM` and `6 P` but not `6PM`, and `6:30.5` as minutes and seconds); `NUMBERVALUE` removes whitespace and the group separators, then parses the rest the same way.
- `CHAR` and `CODE` use the Windows code page of the workbook's locale, Windows-1252 in en-US and Windows-1251 in ru-RU, so a workbook produces the same characters as in Excel for Windows, where most workbooks are created; Excel for Mac maps codes 128–255 by Mac Roman and Mac Cyrillic, a platform encoding rather than the workbook's. Codes 1–127, a code outside 1–255 (`#VALUE!`), the code of a character outside the code page (95, `_`) and argument handling are as Excel calculates them (the `char-code` set, in both locales); the tables are checked against Unicode's published ones. `UNICHAR` and `UNICODE` work with code points.
- `ACCRINT` steps its coupon dates from the first interest date, each from the previous one, so a day shifted by a short month stays shifted (30 August, 28 February, 28 August), and a first interest date on the last day of a month keeps to the last days of months. The period before the settlement counts its days over the length of the regular period that ends at the first interest date (360 days a year on bases 0, 2 and 4, 365 on basis 3), each whole period back to the issue counts as 1, and the issue's own period counts its days over that period's length; a settlement on a coupon date counts the period before it as a fraction (`ACCRINT(DATE(2024,1,1),DATE(2024,7,1),DATE(2025,1,1),0.05,1000,2,1)` is 25·(1 + 184/182)). With calc_method FALSE, the whole periods count as 0 and the settlement's fraction is counted from the start of that regular period, so a settlement before it gives a negative result, as in Excel (`ACCRINT(DATE(2017,1,1),DATE(2017,12,1),DATE(2017,4,1),0.33,3000,4,1,FALSE)` is -253.88). A coupon period that starts before 1900 leaves no coupons: `ACCRINT` is 0 when the issue's period does, and `PRICE` is `#NUM!` when the settlement's period does, since `COUPNUM` finds none. Serial 0 as the issue or first interest date of `ACCRINT`, and any date of 0 in `XNPV`, are `#NUM!`, while `XIRR` accepts it. `AMORDEGRC` and `AMORLINC` depreciate no more than cost minus salvage in the first period, and the period of `AMORDEGRC` that crosses the salvage value takes its whole amount, and later periods nothing.
- `GCD` and `LCM` of nothing but blank cells are `#VALUE!`; `CSCH` and `IMCSCH` keep the digits of a tiny argument (`CSCH(1E-12)` is 1E12); `POISSON.DIST` is `#NUM!` for any x below 0 before it truncates x; `PROB` skips pairs that are not two numbers and is `#DIV/0!` when none is left; `LOGNORM.DIST` near its median computes Φ to the last digit (with erf's series), as Excel does, so `LOGNORM.INV(LOGNORM.DIST(4,3.5,1E12,TRUE),3.5,1E12)` is 3.99976588093441; and `NORM.S.INV` near 0.5 uses Wichura's AS 241.
- `FV` and `PV` compute (1 + rate)^nper as Excel's power does (at a rate of -1, 0 periods give `#NUM!` and fewer `#DIV/0!`), `IRR` returns `#VALUE!` for a guess of -1 or less, `MIRR` returns -1 for flows without an inflow (`#DIV/0!` for a single value or no outflow), and `XNPV` returns `#VALUE!` for a blank first value or date and `#NUM!` for a later one.
- `WORKDAY` and `WORKDAY.INTL` round their days down (`WORKDAY(A1,-1E-9)` is the workday before A1), `DAYS360` takes the day of each moment rounded to the second, as `DAY` does (`DAYS360(45992.000001,46000.999999)` is 9), and `WEEKDAY` reads both arguments before checking the date's range (`WEEKDAY(-1,"abc")` is `#VALUE!`). Time text with minutes or seconds of five digits is not a time (`TIMEVALUE("0:0:86400")` is `#VALUE!`).
- `WORKDAY`, `WORKDAY.INTL`, `NETWORKDAYS` and `NETWORKDAYS.INTL` parse date and numeric text among their holidays, in cells and arrays too (`WORKDAY(A1,5,H1:H3)` with `"1/6/2025"` in H1); other text and booleans there are `#VALUE!`.
- Dates follow Excel's 1900 date system, including the phantom 1900-02-29: `DATE(1900,2,29)` is 60. A workbook can use the 1904 system instead ([Date systems](formulas.md#date-systems)), where the former Analysis ToolPak functions parse date text given as a value as Excel does there: `EDATE("1/31/2025",1)` is 42793, while `EDATE(A1,1)` with that text in A1 is 44254. `DATE` treats a day outside −32768…32767 as 32767 and returns `#NUM!` for a month of 32767 or more, as Excel does.
