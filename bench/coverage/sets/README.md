# Case sets

Excel-verified cases beyond the coverage measurement, one file per set, so parallel branches never edit the same file.

- `bench/coverage/sets/<name>.ts` exports `buildProbes(): Probe[]` (each case with `fn` set to the function it checks) and, if needed, `SHEETS`: extra data sheets as `{ sheet: { A1: value } }`, a cell given as `{ formula }` (Excel's text, with `_xlfn.` prefixes) holding a formula. Cases are computed as dynamic array formulas (Excel 365: no implicit intersection, an array answer spills; in the case book every neighbour is taken, so an answer of more than one value is `#SPILL!`). Sheet names `D` (the measurement's data sheet, also available to sets) and `C` (cases) are taken.
- `npx tsx bench/coverage/run.ts probes <name>` runs the cases in Excel en-US (English UI) under the Excel lock and stores the answers in `test/excel/cases/<name>.json`; `probes <name> ru` runs them in Excel ru-RU (Russian UI and locale) into `test/excel/cases/ru-RU/<name>.json`.
- `test/excel-sets.test.ts` checks that the stored cases equal the generator's and that the engine matches Excel on every case; `test/excel.test.ts` counts a whitelisted function as covered if a set has cases for it. `test/excel-ru-probes.test.ts` does the same for the ru-RU answers, computing in a book with `locale: 'ru-RU'` (known differences in `RU_KNOWN`, `test/excel-ru-cases.ts`).
- Locale sets: `locale` (ru-RU only: text as numbers, dates and booleans, numbers as text, TEXT codes, DOLLAR, FIXED, NUMBERVALUE, complex text, criteria), `collation`, `criteria-text` and `logical-text` (both locales); `date-day` and `format-scale` (en-US) pin rules the ru-RU cases led to; `char-code` and `lead-spaces` (both locales), `date-noyear`, `time-text`, `complex-text` and `arity` (en-US) pin text read as dates, times and complex numbers, CHAR and CODE and the largest argument counts.
- `areas` puts a union and a reference across sheets (`Jan:Mar!A1:A3`, over sheets whose names do not read as cell addresses) into each argument of every whitelisted function that takes a range; a case's id names the function and the argument (`fn:union:SUBTOTAL#2`), so a change of argument kinds moves no other case. `areas-each` measures how SUBTOTAL, AGGREGATE, FREQUENCY and SORTBY take them.
- `intersect` measures the intersection and the range operator between references, `sheet-cells` sheets named like cells (`S1:S3!A1`), `single-values` one value where a function takes a table, an array or dates, `findate-edges` the financial and date functions at edges (ACCRINT on basis 1, coupon periods before 1900, dates of 0, date text among holidays).
- A set measured to settle a question can predict its answers before Excel runs it: `PREDICTED` beside `buildProbes`, committed first, and after the run `MISSED`, the ids Excel answered otherwise (`test/excel-predicted.test.ts` keeps the list exact).
- Size arguments of functions that build arrays (MUNIT, SEQUENCE, EXPAND and the like) take only small numeric literals: a date or numeric text there can exhaust Excel and block it with a modal dialog.
- A formula Excel does not accept when loading a file (for example a wrong number of arguments) makes Excel reject the whole book with a "We found a problem with some content" dialog. The `probes` step closes that dialog (No), splits the part in halves down to the offending formulas, saves the other answers and fails listing them: remove or fix those cases in the generator and run again. The sets `let`, `omit` and their held-out sets keep such formulas in `REFUSED` (the engine's spelling), and `test/let.test.ts` and `test/omitted.test.ts` check that the engine refuses them too.
- A held-out set (`let-held`, `omit-held`) exports `PREDICTED`, the answers predicted and committed before Excel ran it (`refused` for a formula predicted not to load); its cases keep their numbers when refused ones leave. Answers are saved after every part, and a rerun continues from what is stored (`FCOV_FRESH=1` starts over).
- The random check (`fuzz.ts`, generator in `fuzz/`) draws formulas from a seed, each from its own stream, with argument kinds and counts frozen in `fuzz/spec.json`, so a change to the engine's kinds or a fix to one formula's path leaves the stored formulas as they are; a new batch goes last in `BATCHES`. `fuzz/gen.test.ts` checks that size arguments are small literals, that Excel's reference-only positions get references and that every arity is one the function takes. A difference whose cause lies outside the functions goes to `OPEN` in `test/excel-open.ts` (engine answer pinned, one line why), not to `KNOWN`.
