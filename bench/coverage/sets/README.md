# Case sets

Excel-verified cases beyond the coverage measurement, one file per set, so parallel branches never edit the same file.

- `bench/coverage/sets/<name>.ts` exports `buildProbes(): Probe[]` (each case with `fn` set to the function it checks) and, if needed, `SHEETS`: extra data sheets as `{ sheet: { A1: value } }`, a cell given as `{ formula }` (Excel's text, with `_xlfn.` prefixes) holding a formula, and `DYNAMIC = true` to have the cases computed as dynamic array formulas (Excel 365: no implicit intersection, an array answer spills; in the case book every neighbour is taken, so an answer of more than one value is `#SPILL!`). Without it a case is a formula of the old kind. Sheet names `D` (the measurement's data sheet, also available to sets) and `C` (cases) are taken.
- `npx tsx bench/coverage/run.ts probes <name>` runs the cases in Excel en-US (English UI) under the Excel lock and stores the answers in `docs/excel-cases/<name>.json`.
- `test/excel-sets.test.ts` checks that the stored cases equal the generator's and that the engine matches Excel on every case; `test/excel.test.ts` counts a whitelisted function as covered if a set has cases for it.
- Size arguments of functions that build arrays (MUNIT, SEQUENCE, EXPAND and the like) take only small numeric literals: a date or numeric text there can exhaust Excel and block it with a modal dialog.
- A formula Excel does not accept when loading a file (for example a wrong number of arguments) makes Excel reject the whole book with a "We found a problem with some content" dialog. The `probes` step closes that dialog (No), splits the part in halves down to the offending formulas, saves the other answers and fails listing them: remove or fix those cases in the generator and run again. Answers are saved after every part, and a rerun continues from what is stored (`FCOV_FRESH=1` starts over).
