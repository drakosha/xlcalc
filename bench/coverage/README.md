# Замер покрытия formulajs против Excel

Сколько функций `@formulajs/formulajs` 4.6.1 дают тот же ответ, что Excel, голые и через адаптер по правилам рантайма движка. Код замера живёт здесь и в пакет не попадает; отчёт и сырые результаты в `docs/coverage-formulajs.md` и `docs/coverage-formulajs/`.

## Как повторить

```sh
npx tsx bench/coverage/run.ts all
```

Отдельный шаг `probes` считает в Excel en-US пробы вне замера (`probes.ts`: число в текст, TEXT с General, длинные литералы, условия по целым колонкам разных листов) и пишет случаи с ответами в `docs/excel-probes.json`; их сверяет `test/excel-probes.test.ts`. Набор `sets/<имя>.ts` считается тем же шагом (`probes <имя>`) в Excel en-US в `docs/excel-cases/<имя>.json` или, с третьим аргументом `ru` (`probes <имя> ru`), в Excel ru-RU в `docs/excel-cases/ru-RU/<имя>.json`; ответы ru-RU сверяет `test/excel-ru-probes.test.ts` в книге с `locale: 'ru-RU'`, колонку ru-RU замера `test/excel-ru.test.ts`. Пробы `probes.ts` считаются только в en-US. Шаг `all` делает по очереди: случаи и книгу, formulajs, LibreOffice, Excel en-US, Excel ru-RU, отчёт. Каждый шаг можно запускать отдельно (`cases`, `fj`, `lo`, `excel en`, `excel ru`, `report`), каждый пишет свой JSON в `docs/coverage-formulajs/`. Пробный прогон на нескольких функциях: `FCOV_ONLY=SUM,TEXT npx tsx bench/coverage/run.ts cases`, потом нужные шаги; тогда всё пишется в `bench/coverage/out/` (в git не попадает). Тест генератора: `npx vitest run bench/coverage`.

Шаг `struct <набор>` проверяет операции над структурой книги (вставка и удаление строк и колонок, перенос и копирование диапазонов, переименование и удаление листа): `struct/<набор>.ts` задаёт книги и по одной операции на случай, Excel en-US применяет операцию к книге (`excel-struct.applescript`, предупреждения на время операции выключены), формулы листов и определения имён читаются обратно и пишутся в `docs/excel-struct/<набор>.json`; их сверяет `test/structure-excel.test.ts`. Операцию, от которой Excel отказывается, AppleScript возвращает ошибкой, без окна. `FSTRUCT_ONLY=id,id` прогоняет только эти случаи.

Нужны: Node 24+, `soffice` в PATH (LibreOffice), Excel для Мака (замер делался на 16.113) и разрешение на управление Excel и System Events из терминала (Автоматизация и Универсальный доступ в настройках macOS).

## Устройство

- `excel-functions.json`: список функций со страницы Microsoft «Excel functions (alphabetical)» (имя, категория, версия появления).
- `signatures.ts`: таблица сигнатур функций из набора: виды аргументов и типичные вызовы, ручные краевые случаи, приставки `_xlfn.`, страж размеров массивов.
- `data.ts`: лист данных синтетической книги (лист `D`).
- `cases.ts`: генератор случаев; `cases.test.ts` проверяет стража размеров по всем случаям.
- `formulajs.ts`, `fj-worker.ts`: вызов formulajs через адаптер и голой в дочернем процессе; случай, который висит дольше 5 с, убивается и помечается.
- `book.ts`: книга xlsx (ExcelJS, без кэша значений).
- `libreoffice.ts`: пересчёт `soffice --headless` с профилем en-US, чтение XML.
- `excel.ts`, `excel-read.applescript`: Excel через `osascript`.
- `sets/fuzz.ts`, `sets/fuzz/`: случайная проверка, формулы по белому списку из зерна (виды и число аргументов заморожены в `sets/fuzz/spec.json`, у каждой формулы свой поток случайных чисел); `sets/fuzz-rules.ts`: правила Excel, которые она нашла, случаями.
- `compare.ts`, `report.ts`: сравнение и таблицы отчёта. Таблицы стоят в отчёте между метками `<!-- auto:имя -->` и пересобираются шагом `report`; текст вне меток пишется руками.

## Правила работы с Excel

Их нарушение стоило двух модальных диалогов и трёх падений Excel при подготовке замера.

- Книга кладётся в песочницу Excel `~/Library/Containers/com.microsoft.Excel/Data/tmp/fcov-<pid>/`: оттуда Excel открывает её без запроса доступа. После части каталог удаляется.
- Открытие: путь HFS вычисляется до блока `tell` (`set hfs to (POSIX file p) as text`), затем `open workbook workbook file name hfs`. С `POSIX file p` внутри `tell` Excel отвечает ошибкой параметра (-50).
- Чтение: `value of range` читается только с колонок без ошибок. Значения-ошибки из `value` диапазона выпадают из списка (позиции сдвигаются), а чтение двумерного диапазона с ошибками роняло Excel (ошибка -609). Поэтому рядом с формулой случая (колонка A) в книге три колонки-обёртки, которые ошибку не дают никогда: B код типа (0 число, -1 TRUE, -2 FALSE, -3 текст, больше 0 номер `ERROR.TYPE`), C число, D текст. Три колонки читаются тремя вызовами и отдаются через `NSJSONSerialization` (ASObjC): так числа приходят с полной точностью, а печать вещественных через `osascript` теряет знаки.
- Расчёт: `calculate full`, затем `close wb saving no`.
- Функции новее Excel 2007 пишутся с приставкой (`_xlfn.XLOOKUP`, `_xlfn._xlws.SORT`), список в `signatures.ts`. Пропущенная приставка видна как `#NAME?` на всех случаях функции; в замере таких нет.
- Шаг `excel` замера (с 6 октября 2026 года, прежние колонки в `excel-en-legacy.json` и `excel-ru-legacy.json`), пробы `probes.ts` и все наборы (у каждого `DYNAMIC = true`) пишут формулы случаев формулами динамического массива, как их сохраняет Excel 365: `cm="1"` у ячейки, `<f t="array" ref="A1">` и метаданные XLDAPR (`fDynamic="1"`) в `xl/metadata.xml` (`book.ts`). Такая формула считается без неявного пересечения, ответ-массив растекается; соседи случая заняты, под последним случаем заглушка, поэтому ответ больше одной ячейки всегда `#SPILL!`. Обёртка `SUM(...)` в формуле старого вида не помогает: пересечение делается внутри неё (`SUM(D!B1:B8*2)` старой формулой в строке 2 даёт 16).
- Формулы старого вида пишет только набор без `DYNAMIC` (сейчас таких нет: `criteria`, `findate`, `stat`, `subtotal` и пробы пересчитаны динамическими 6 октября, изменился один ответ из 5 824). Там случай с ответом-массивом (INDEX, ROWS или COLUMNS над функцией-массивом) пишется формулой массива (`t="array"`, как ввод Ctrl+Shift+Enter): в обычной формуле старого вида Excel применяет к аргументу TRANSPOSE неявное пересечение и даёт `#VALUE!`.
- Размер массива из аргумента (MUNIT, EXPAND, TAKE, DROP): в позиции размера только маленькие числовые литералы (не больше 100), без ссылок, текста и дат. `MUNIT(45688)` и `MUNIT("1.5")` в ru-RU (текст стал датой 46143) исчерпали ресурсы Excel и вызвали модальный диалог. Для прочих аргументов-размеров и счётчиков (REPT, порядок BESSEL, периоды, дни WORKDAY) «большое» значение 1000, дата и `"1.5"` не подставляются.
- Excel считается частями до 400 случаев, по целым функциям. До и после каждой части через System Events проверяется, нет ли у Excel окна, которое не окно книги (подроль не `AXStandardWindow`). Есть: прогон останавливается, текст окна и номер части пишутся в `meta.stopped` файла колонки, ничего не нажимается. Если System Events отвечает на опрос ошибкой -1719 (окно книги закрылось во время опроса), опрос повторяется, до трёх раз (`excelDialogs` в `excel.ts`, общий для всех шагов). Посчитанные части остаются в файле, повторный запуск продолжает с первой непосчитанной (`FCOV_FRESH=1` заново).
- Язык интерфейса и локаль расчёта задаются аргументами запуска, настройки Excel (`defaults write`) не меняются. Для en-US Excel запускается `open -a "Microsoft Excel" --args -AppleLanguages '(en)' -AppleLocale en_US`, для ru-RU без аргументов (системные русские язык и локаль). Перезапуск только при нуле открытых книг: `quit`, ожидание выхода, `open -a`. AppleEvent шлётся только запущенному Excel: `tell application "Microsoft Excel"` при незапущенном Excel запускает его без аргументов. Пустую новую книгу, которую Excel открывает при запуске («Book1» с английским интерфейсом, «Книга1» с русским; без файла и без правок), шаг закрывает без сохранения до первой части, так что ни счётчик книг, ни проверка окон на неё не спотыкаются. Шаг `all` кончается на ru-RU, так что Excel остаётся запущенным без аргументов.
- Язык интерфейса влияет на расчёт, не только на показ, поэтому для en-US нужен и английский интерфейс, а не одна локаль. С русским интерфейсом текст `"TRUE"` не логическое (`IF("TRUE",1,2)` это `#VALUE!`, зато `IF("ИСТИНА",1,2)` это 1), логическое в тексте выходит `ИСТИНА` (`TRUE&""`), `CODE("Ж")` берёт кодировку Mac Cyrillic (134 против 95). Первая колонка en-US была посчитана с локалью en_US и русским интерфейсом и разошлась с правильной в 32 случаях; она оставлена в `docs/coverage-formulajs/excel-en-ru-ui.json`, отчёт сравнивает её с текущей. Тексты ошибок Excel показывает на языке интерфейса; замер их не читает, код ошибки берётся из `ERROR.TYPE`.
- Ответ Excel не всегда воспроизводится. `VLOOKUP(5,D!L1:N6,D!E2:E4,FALSE)` (номер колонки из диапазона с ячейкой-формулой `1/0`) в одной книге давал то `#REF!`, то `#VALUE!` в зависимости от строки и прогона: похоже на порядок пересчёта. `DAY(WEEKNUM(40977,1E+3)<>2.5)` в книге случайной проверки дважды дал 1, а один и в маленькой книге `#NUM!`. Расхождение со случаем, который трогает такие места, сначала проверить повторным прогоном и отдельной книгой.
- Если Excel показал диалог, завис или просит ручного действия: остановиться и сообщить, диалог не закрывать и не обходить.
- Имена переменных AppleScript внутри `tell application "Microsoft Excel"` не должны совпадать с терминами словаря Excel: переменная `a1` там читается как константа стиля ссылок `A1`, и `worksheet a1` даёт «объект не существует». Так же `tab`: внутри блока вместо него `character id 9`.
