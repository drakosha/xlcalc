# The coverage measurement and Excel's answers

Two things live here, outside the package. The coverage measurement: how many functions of `@formulajs/formulajs` 4.6.1 give Excel's answer, bare and through an adapter following the engine's runtime rules; its report is `docs/coverage-formulajs.md`. And the harness that computes Excel's answers for the engine's tests: the measurement's cases, the probes, the case sets, structure operations and spilling.

## Where the data are

Excel's answers are stored, so the tests run without Excel. Everything the tests read is in `test/excel/`. en-US's answers are at the top of each directory, another locale's in a directory named by its tag (`ru-RU/`), as `locales.ts` names them:

- `coverage/`: the measurement. `cases.json` holds the cases with their formulas (written by `cases.ts`), `excel-en.json` and `excel-ru.json` Excel's columns, and `excel-<tag>.json` another locale's. Tests: `test/excel.test.ts`, `test/excel-locales.test.ts`.
- `cases/<set>.json`: the case set `sets/<set>.ts` computed in Excel en-US; `cases/ru-RU/<set>.json` the same set in Excel ru-RU. Tests: `test/excel-sets.test.ts`, `test/excel-locales-sets.test.ts`.
- `probes.json`: the probes of `probes.ts`. Test: `test/excel-probes.test.ts`.
- `struct/<set>.json`: the structure operations of `struct/<set>.ts`. Test: `test/structure-excel.test.ts`.
- `spill/<set>.json`: the spill cases of `spill/<set>.ts`; `order-runs.json` keeps every answer seen for the pairs of arrays whose order Excel varies. Test: `test/spill-excel.test.ts`.
- `tables/<set>.json`, `tables/ru-RU/<set>.json`: the books with tables of `tables/<set>.ts`, the steps Excel took on them and what it showed after: values, formulas (in Russian too for a ru-RU set) and tables. Test: `test/tables-excel.test.ts`.
- `workbook/<set>.json`: the books of `workbook/<set>.ts`, whose files hold what the cells alone do not (hidden rows and columns, filters, the 1904 date system, iterative calculation, stored values), and what Excel showed at each step. Test: `test/workbook-excel.test.ts`.
- `display/<set>.json`, `display/ru-RU/<set>.json`: what cells show, from `display/<set>.ts`. Test: `test/display-excel.test.ts`.
- `entry/<set>.json`, `entry/ru-RU/<set>.json`: text typed into cells, from `entry/<set>.ts`, with the day of the run. Tests: `test/entry-excel.test.ts`, `test/entry.test.ts`.
- `locale/ru-RU.json`: Excel's ru-RU formula text and international settings, written by `bench/locale/snapshot.ts ru`; `bench/locale/generate.ts ru-RU` writes the formula text of `src/locales/ru-RU.ts` from it. Another locale's is `locale/<tag>.json`. Test: `test/locale-excel.test.ts`.
- `xlsx/`: the files Excel saved for the xlsx subpath, in `roundtrip/`, `saved/`, `intersect/` and `filters/`, with `roundtrip.json`, `saved.json`, `intersect.json` and `filters.json` recording what was sent (a hash per book); `colors.json` and `formats.json` hold the fill colours and the built-in number formats Excel shows. Test: `test/xlsx-excel.test.ts`.
- `parts/<set>.json` and `parts/<set>/<id>.xlsx`: notes, hyperlinks and frozen panes, `parts/<set>.ts`: what Excel read in every sheet of each case's book, and the file it saved. Tests: `test/sheet-parts-excel.test.ts`, and `test/sheet-parts-win.test.ts` for Windows's.
- `cond/<set>.json` and `cond/<set>/<id>.xlsx` (`cond/ru-RU/` for a set of ru-RU): conditional formats, `cond/<set>.ts`: what the read cells showed by their display format after each case, and the file Excel saved. Tests: `test/cond-excel.test.ts`, and `test/cond-win.test.ts` for Windows's.
- `valid/<set>.json`, `valid/ru-RU/<set>.json` and the folders beside them: data validation and outlines, `valid/<set>.ts`: what Excel read over each sheet's window in each case's book (each cell's rule and `Validation.Value`, the outline), and the file it saved. Tests: `test/validation-excel.test.ts`, and `test/validation-win.test.ts` for Windows's.
- `fit/<set>.json`, `fit/ru-RU/<set>.json`: column widths, from `fit/<set>.ts`: each case's column as Excel fitted it or widened it for the texts typed, its width as the object model reports it and as the saved file holds it (`<col>` width, `customWidth`, `bestFit`), and what its cells show, with the day of the run. Test: `test/fit-excel.test.ts`.
- `hidden/<set>.json` and `hidden/<set>/<id>.xlsx`: hidden sheets, `hidden/<set>.ts`: each sheet's visibility, the active sheet and the read cells' values Excel read in each case's book, and the file it saved. Test: `test/hidden-sheets-excel.test.ts`, for Windows's too.
- `win/`: Excel for Windows's answers to the same books, in the same layout, written by `bench/windows` (its README). Tests: `test/excel-win.test.ts` and the other `*-win.test.ts`.

What only the report reads is in `bench/coverage/data/`: `formulajs.json` (formulajs through the adapter and bare), `libreoffice.json` and `summary.json` (the verdicts by case and function, written by the `report` step).

Nobody edits these files by hand: each is written by the step that names it below, and a new run keeps the stored answers of the cases that did not change.

## Running it

```sh
npx tsx bench/coverage/run.ts all
```

The step `all` does in turn: the cases and the book, formulajs, LibreOffice, Excel en-US, Excel ru-RU, the report. Each step runs alone too (`cases`, `fj`, `lo`, `excel en`, `excel ru`, `report`) and writes its JSON: the cases and Excel's columns to `test/excel/coverage/`, formulajs, LibreOffice and the summary to `bench/coverage/data/`. A trial run on a few functions: `FCOV_ONLY=SUM,TEXT npx tsx bench/coverage/run.ts cases`, then the steps needed; everything then goes to `bench/coverage/out/` (not in git). The generator's test: `npx vitest run bench/coverage`.

The step `probes` computes in Excel en-US the probes outside the measurement (`probes.ts`: numbers as text, TEXT with General, long literals, criteria over whole columns of different sheets) and writes the cases with their answers to `test/excel/probes.json`. A set `sets/<name>.ts` is computed by the same step (`probes <name>`) in Excel en-US into `test/excel/cases/<name>.json` or, with a third argument `ru` (`probes <name> ru`), in Excel ru-RU into `test/excel/cases/ru-RU/<name>.json`; `test/excel-locales-sets.test.ts` checks the ru-RU answers in a book with `locale: 'ru-RU'`. The probes of `probes.ts` are computed in en-US only. How to write a set: `sets/README.md`.

The step `struct <set>` checks operations on a book's structure (inserting and deleting rows and columns, moving and copying ranges, renaming, deleting, inserting and moving a sheet): `struct/<set>.ts` gives the books and one operation per case, Excel en-US applies the operation to the book (`excel-struct.applescript`, alerts off during the operation), and the sheets' formulas and the names' definitions are read back into `test/excel/struct/<set>.json`. An operation Excel refuses comes back from AppleScript as an error, with no window. Changing part of an old-kind array formula's area Excel refuses without an error: the book stays as it was, and the test takes that as a refusal. A cell with `array` is written as an array formula of the old kind over its area. `FSTRUCT_ONLY=id,id` runs only those cases. A set may name more rectangles whose look is read (`look`, the sheet's end), and leave column widths out of the comparison (`widths: false`) where Excel takes a span over most columns as the sheet's standard width when it loads the book. A row of height 0 is written by the step itself (`ht="0"`), as ExcelJS leaves it out. `npx tsx bench/coverage/struct/predict.ts <set>` writes the engine's answers to `struct/<set>.predicted.json` (a refusal, or each sheet's look and cells), to commit before Excel runs a held-out set.

The step `legacy <set>` computes the set `legacy/<set>.ts` as the `probes` step does, but writes its formulas as formulas of the old kind and reads each back as Excel 365 shows it (`formula2`, with `@` where Excel intersects). It stores the answers, the texts and each case's row in `test/excel/legacy/<set>.json`; `test/legacy.test.ts` checks `fromLegacy` against the texts and the values. `legacy/table.ts` writes `src/legacy/params.ts` from the sets `params` and `nesting`. `test/excel/legacy/measurement.json` is the coverage measurement as Excel computed it with formulas of the old kind, restored from `docs/coverage-formulajs/excel-en-legacy.json` at commit `85522cf`.

The step `spill <set>` checks spilling arrays: `spill/<set>.ts` gives small books whose formulas are written as dynamic array formulas (`E2#` as `_xlfn.ANCHORARRAY(E2)`), Excel computes the book, and the values of a case's rectangles are read through the mirror sheets `WT`, `WN`, `WX`: three formulas per cell that never give an error (type code, number, text), plus the rectangles' own formulas. The answers go to `test/excel/spill/<set>.json`. `FSPILL_ONLY=id,id` runs only those cases. The set `held` was held out: its answers were predicted and committed before the run. A case may have `edits`: values typed into cells, formulas entered (as Excel 365 enters them) or cells cleared, a range at once too, after Excel computed the book, Excel recalculating after each; the test applies them in a session, and an edit the engine refuses leaves the book as Excel leaves it. A book's names keep their scope and may hold any formula. A cell with `array` is written as an array formula of the old kind over its area (`t="array"` without `cm`), and the cells a case lists in `legacy` as formulas of the old kind; their text as Excel 365 shows it (`formula2`) is read too, and the test converts them with `fromLegacy`. `@x` is written `_xlfn.SINGLE(x)`. A book Excel does not load is recorded as `rejected` and the run goes on.

The step `xlsx <step>` checks the xlsx subpath (`xlsx.ts`, `xlsx/`). Excel opens each file, computes it fully and saves it under another name (`excel-save.applescript`), and the saved file is stored. `roundtrip` sends the books of `xlsx/books.ts` (made-up books, the synthetic book, the books of the struct and spill sets) as `writeXlsx` writes them with the engine's values. `saved` sends the parts of every case set with stored answers, and the probes, as `book.ts` writes them. `intersect` sends formulas of the old kind (`xlsx/intersect.ts`) without dynamic array metadata; read with `@` where Excel puts it, they must compute the values Excel stored. `filters` sends files with a filter in each form a file holds it (`xlsx/filters.ts`: an autofilter with criteria with and without the sheet's mark, one without criteria, an advanced filter's mark, a table's filter), put by hand into what `writeXlsx` wrote; read with the filter mode Excel took, they must compute the values Excel stored. `npx tsx bench/coverage/xlsx/predict.ts` writes the engine's answers to the filter files and to the round trip's books it names to `xlsx/predicted.json`, to commit before Excel runs them. `colors` and `formats` read the fill colours and built-in number formats Excel shows for a book written by hand (`xlsx/colors.ts`, `xlsx/formats.ts`, `excel-colors.applescript`, `excel-formats.applescript`). A run sends again only the books whose bytes or cases changed (`FCOV_FRESH=1` sends all) and drops the files of books it no longer sends; `FXLSX_ONLY=id,id` limits it. The repair window "We found a problem with some content" on a written file is the writer's fault: the step closes it with No and records the book as rejected. `xlsx/generate.ts` (not a step) writes the subpath's table of `_xlfn.` prefixes.
The step `workbook <set>` writes each book of `workbook/<set>.ts` with the parts of its file the model lacks or that a case sets: hidden rows and columns, an autofilter with its criteria, `date1904`, `calcPr iterate`, values stored for formulas, formulas of the old kind. Excel opens the book and takes the case's steps: a full calculation, a recalculation, a value or a formula typed in, rows hidden or shown, a filter, a read. A read takes the rectangles' values through the mirror sheets, as the spill step does, and the shown text of the cells a case lists. The answer also records Excel's iteration settings after opening. `FBOOK_ONLY=id,id` runs only those cases. A book with a circular reference and no iterative calculation is refused before Excel opens it, because Excel would show a warning window. Formulas over a cycle's cells change Excel's first computation when their sheet sorts before the cycle's, so the set `iterate` names the mirror sheets to sort last.

The step `tables <set> [ru]` checks tables (`tables.ts`, `excel-tables.applescript`). `writeXlsx` writes each book of `tables/<set>.ts` with three empty mirror sheets; Excel opens it, computes it and takes the case's steps (a value, a formula or a formula in the user's language typed in, a cell cleared, rows and columns inserted and deleted, ranges moved and copied, sheets renamed and deleted, tables renamed, converted and deleted, a defined name added through the object model, `make new named item` and on Windows `Names.Add`), with alerts off; a step Excel refuses comes back with its error, and some Excel refuses without one, leaving the book as it was. Then the mirror formulas are written over the rectangles where the steps left them, and the values, the formulas (`formula`, and `formula local` for a ru-RU set) and every sheet's tables are read, and for a case that adds names the visible names Excel lists (a sheet's own as `Sheet!name`). The object model refuses a defined name Excel does not take with an error (-50 on the Mac), while it makes a name of a table's name it does not take (`AB12_`). Typed numbers go through `NSString`'s `doubleValue`, as AppleScript's `as number` reads the system's decimal separator. A book Excel would repair is declined: Excel shows that window on another Space, where System Events does not list it, so the step activates Excel when a book does not open. Some books Excel refuses at `open workbook` with error -50 and shows no window at all (Excel ru-RU, a defined name `ИСТИНА`); the step records them as not loaded too. `FTABLES_ONLY=id,id` runs only those cases, `FTABLES_AGAIN=id,id` runs those again. `npx tsx bench/coverage/tables/predict.ts <set>` writes the engine's answers to `tables/<set>.predicted.json`, to commit before Excel runs a held-out set.

The step `parts <set>` checks notes, hyperlinks and frozen panes (`parts.ts`, `excel-parts.applescript`). Each book of `parts/<set>.ts` is written by `writeXlsx` (a set's `threads` are put into the file by hand, `parts/threaded.ts`, as neither Excel makes them through its object model); Excel opens it, makes the case's notes, hyperlinks and frozen panes through its object model (`add comment`, `make new hyperlink`, the window's `freeze panes`), applies its structure operation, reads every sheet's notes (through `special cells` of the comments type), hyperlinks (address, sub address, screen tip) and window (frozen or split, the split's row and column, the first row and column of its first pane), and saves the book. The answers go to `test/excel/parts/<set>.json` with what was sent (`partsHash` of each file), the saved files to `test/excel/parts/<set>/`. `FPARTS_ONLY=id,id` runs only those cases. `npx tsx bench/coverage/parts/predict.ts <set>` writes the engine's answers to `parts/<set>.predicted.json`, to commit before Excel runs a held-out set.

The step `cond <set>` checks conditional formats (`cond.ts`, `excel-cond.applescript`, `docs/conditional-formats.md`). Each book of `cond/<set>.ts` is written by `writeXlsx`; Excel opens it in the set's locale (`locale` of the set, en-US without one), applies the case's structure operation, computes the book, reads each listed cell's `string value` and its display format's fill colour and colour index, font colour, bold and italic (what conditional formats show), and saves the book. The answers go to `test/excel/cond/[<tag>/]<set>.json` with what was sent (`partsHash` of each file), the saved files beside them. A case whose rules Excel makes itself (`make`) is Windows's alone: `make new format condition` stopped Excel for Mac 16.113, which came back in ru-RU with its window of recovered books. The step activates each sheet before reading it, as `cell j of` a range of a sheet that is not active gives the active sheet's cell. `FCOND_ONLY=id,id` runs only those cases. `npx tsx bench/coverage/cond/predict.ts <set> [run]` writes the engine's answers to `cond/<set>.predicted.json` (`<set>.<run>.predicted.json` for a later run), to commit before Excel runs a set.

The step `valid <set> [ru]` checks data validation and outlines (`valid.ts`, `excel-valid.applescript`). Each book of `valid/<set>.ts` is written by `writeXlsx`; Excel opens it, makes the case's rules (`add data validation` with the range's first cell selected, as a rule's relative references are relative to the active cell, then its properties), groups (`group` on whole rows or columns) and collapsed groups (`show detail` false on a summary line) and summary settings, applies its structure operation, and over the set's window of every sheet reads each cell that has a rule (`special cells` of all validation, areas split at the locale's list separator), with the cell selected: its type, operator, formulas, settings and texts, and `value` of its validation, whether the cell's value meets it; then each line's outline level, hidden state and, for a summary line, whether its detail is shown, and the sheet's summary settings; and saves the book. The answers go to `test/excel/valid/[ru-RU/]<set>.json` with what was sent (`partsHash`), the saved files beside them. `FVALID_ONLY=id,id` runs only those cases. `npx tsx bench/coverage/valid/predict.ts <set>` writes the engine's answers to `valid/<set>.predicted.json`, to commit before Excel runs a set. In ru-RU the object model shows a rule's formulas now in Russian, now in English, and makes no rule of a formula with a Russian function name.

The step `entry <set> [ru|<tag>]` checks text typed into cells (`entry.ts`, `excel-entry.applescript`, `docs/entry.md`). `entryBook` writes the cases of `entry/<set>.ts` with `writeXlsx` into books of up to 100 cells, column A of the sheet `S` in General or with the case's format set before, and data in column C for the typed formulas to read (never column A, whose cells the texts go into). Excel types each text into its cell through `formula2 local`, as Excel 365 takes typed text in the user's language, with alerts off; then each cell's `string value`, `number format`, `number format local` and `prefix character` are read, the book is saved as xlsx, and `readXlsx` reads from the saved file what each cell holds (its value or formula and format) and a formula's value. A formula Excel does not take leaves the cell blank with no error from AppleScript: the step marks it refused. A set that exports `keys = true` is typed on the keyboard instead (System Events, Excel in front, checked before each text; the keyboard layout must type every character of the set, ASCII on this Mac's ABC layout): the window Excel shows for a formula it does not take ("We found a typo in your formula", then why the formula is not taken) is answered with No and OK, and Escape leaves the cell as it was; the step does not stop on these windows, and the text of what was answered is the case's refusal; the handlers that type are in `excel-keys.applescript`, shared with the step `fit`. The number each cell holds is read through the object model too (`value`, a number only, not from a cell that shows an error), which the test checks against the saved file. `FENTRY_ONLY=id,id` runs only those cases. `npx tsx bench/coverage/entry/predict.ts <set>` writes `parseEntry`'s answers in every locale of `LOCALES` to `entry/<set>.predicted.json`, to commit before Excel runs a set.

The step `fit <set> [ru|<tag>]` checks column widths (`fit.ts`, `excel-fit.applescript`, `docs/formats.md`, "Fitting columns"). `fitBook` writes the cases of `fit/<set>.ts` with `writeXlsx` into books of up to 60 columns, each case in its own column of the sheet `S` (B, D, F…, so a cell can be merged with the empty column to its right), its cells, its width set by hand, its format and merged areas as the case gives them; row 30 is hidden across the sheet for the cases about hidden rows. Excel fits each case's column (`autofit` of its entire column) or types its texts into its cells in turn, through `value` or `formula2 local` with alerts off or on the keyboard as the entry step does (`excel-keys.applescript`; the keyboard layout must type every character, so a set leaves out the texts it cannot), after fitting the column when the case says so; then each column's `column width`, `width` and `use standard width` and what its cells show are read, and the book is saved as xlsx, whose `<col>` elements give the width Excel stores and its flags. `FFIT_ONLY=id,id` runs only those cases. `npx tsx bench/coverage/fit/predict.ts <set>` writes the engine's answers in every locale of `LOCALES` to `fit/<set>.predicted.json`, to commit before Excel runs a set.

The step `hidden <set>` checks hidden sheets (`hidden.ts`, `excel-hidden.applescript`). Each book of `hidden/<set>.ts` is written by `writeXlsx`, or changed by hand after it (`raw`: the active tab on a hidden sheet, every sheet hidden); Excel opens it, notes its active sheet, sets the case's sheets' `visible` (sheet visible, sheet hidden, sheet very hidden), applies its sheet operation (rename, delete, insert, move), recalculates, reads each sheet's visibility, the active sheet and the values of the set's read cells (formulas that never give an error, as reading one stops Excel), and saves the book. A step Excel refuses comes back as `error`; Excel for Mac deletes no very hidden sheet and not the last visible one and answers nothing, which the test takes from the sheets left as they were. The answers go to `test/excel/hidden/<set>.json` with what was sent (`partsHash`), the saved files beside them. `FHIDDEN_ONLY=id,id` runs only those cases. `npx tsx bench/coverage/hidden/predict.ts <set>` writes the engine's answers to `hidden/<set>.predicted.json`, to commit before Excel runs a set.

`npx tsx bench/coverage/workbook/predict.ts <set>` writes the engine's answers to a set as its predictions, `workbook/<set>.predicted.json`, to commit before Excel runs a set held out.

A display case with `numFmtId` writes the built-in format of that number without a code, as Excel stores it, and reads back the code Excel reports for it in both forms (`NumberFormat` and `NumberFormatLocal`). A structure case with `via` applies a copy through Excel's Fill Down or fill handle instead of copy and paste, and a structure set's `files` adds an autofilter to the books of filtered sheets.

Stored answers are written in the order of their cases, so a run that adds cases changes only their lines (`stored.ts`, checked by `stored.test.ts`).

Needed: Node 24+, `soffice` on `PATH` (LibreOffice), Excel for Mac (the measurement used 16.113) and permission for the terminal to control Excel and System Events (Automation and Accessibility in the macOS settings).

### Another locale

The steps that take a locale (`excel`, `probes <set>`, `display <set>`, `tables <set>`) take `en`, `ru` or a tag such as `de-DE` as their last argument, and store its answers in a directory of the tag: `probes <set> de-DE` writes `test/excel/cases/de-DE/<set>.json`, `excel de-DE` writes `test/excel/coverage/excel-de-DE.json`. `npx tsx bench/locale/snapshot.ts de-DE` takes its formula text before its locale file exists. The tests take a locale's answers once the locale is in `src/locales/` and name a locale without them as skipped; a directory of answers for a tag the package lacks fails `locales.test.ts`. Where the engine knowingly differs from a locale's Excel is listed as `docs/locale.md` describes ([Tests and harnesses](../../docs/locale.md#tests-and-harnesses)).

Excel starts in another locale with `-AppleLanguages (de) -AppleLocale de_DE`, the form en-US's arguments have; it has not been tried with a third language yet. The window "We found a problem with some content" is known by its English and Russian text (`REPAIR` and `declineRepair` in `excel.ts`): in another interface language a book Excel refuses is not declined, and the step stops when its three minutes run out.

## The code

- `excel-functions.json`: the function list of Microsoft's page "Excel functions (alphabetical)" (name, category, the version that brought it).
- `signatures.ts`: the signature table of the set's functions: argument kinds and typical calls, hand-written edge cases, the array-size guard, and `XLFN`, the one table of `_xlfn.` prefixes the measurement and every case set write (`xl` in `sets/arrays/common.ts`).
- `data.ts`: the data sheet of the synthetic book (sheet `D`).
- `cases.ts`: the case generator; `cases.test.ts` checks the size guard over every case.
- `formulajs.ts`, `fj-worker.ts`: formulajs called through the adapter and bare in a child process; a case that hangs for over 5 s is killed and marked.
- `book.ts`: the xlsx book (ExcelJS, no cached values), its case formulas written as dynamic array formulas, and `READ_COLUMNS`, the formulas that read a cell without an error (type code, number, text), which the mirror sheets of `case-book.ts` use too; `excel.ts` turns what they read back into values (`typedValue`). `case-book.ts` writes the books of the steps `spill` and `workbook`, and its formula cells and names serve `struct.ts` too.
- `libreoffice.ts`: recalculation by `soffice --headless` with an en-US profile, reading the XML.
- `excel.ts`, `excel-read.applescript`: Excel through `osascript`.
- `sets/fuzz.ts`, `sets/fuzz/`: the random check, formulas over the whitelist from a seed (argument kinds and counts frozen in `sets/fuzz/spec.json`, each formula with its own stream of random numbers); `sets/fuzz-rules.ts`: the Excel rules it found, as cases.
- `compare.ts`, `report.ts`: the comparison and the report's tables. The tables stand in the report between the marks `<!-- auto:name -->` and are rebuilt by the `report` step; the text outside the marks is written by hand.

## Rules for working with Excel

Breaking them cost two modal dialogs and three Excel crashes while the measurement was prepared.

- A book goes into Excel's sandbox `~/Library/Containers/com.microsoft.Excel/Data/tmp/fcov-<pid>/`: Excel opens it from there without asking for access. The directory is removed after the part.
- Opening: the HFS path is computed before the `tell` block (`set hfs to (POSIX file p) as text`), then `open workbook workbook file name hfs`. With `POSIX file p` inside `tell` Excel answers with a parameter error (-50).
- Reading: `value of range` is read only from columns without errors. Error values drop out of a range's `value` list (positions shift), and reading a two-dimensional range with errors crashed Excel (error -609). So next to a case's formula (column A) the book has three wrapper columns that never give an error: B the type code (0 number, -1 TRUE, -2 FALSE, -3 text, above 0 the `ERROR.TYPE` number), C the number, D the text. The three columns are read in three calls and handed over through `NSJSONSerialization` (ASObjC): numbers arrive with full precision, while printing reals through `osascript` loses digits.
- Calculation: `calculate full`, then `close wb saving no`.
- Functions newer than Excel 2007 are written with a prefix (`_xlfn.XLOOKUP`, `_xlfn._xlws.SORT`), listed in `signatures.ts`. A missing prefix shows as `#NAME?` on every case of the function; the measurement has none. LET's names are written `_xlpm.x` where declared and used in their scope (`sets/let/xlpm.ts`, also by the spill harness); a word without the prefix is a defined name.
- Every case formula, of the measurement, the probes and the sets, is written as a dynamic array formula, as Excel 365 saves it: `cm="1"` on the cell, `<f t="array" ref="A1">` and the XLDAPR metadata (`fDynamic="1"`) in `xl/metadata.xml` (`book.ts`). Such a formula is computed without implicit intersection and an array answer spills; a case's neighbours are taken and a stub stands under the last case, so an answer larger than one cell is always `#SPILL!`. A `SUM(...)` wrapper does not help a formula of the old kind: the intersection happens inside it (`SUM(D!B1:B8*2)` as an old formula in row 2 gives 16). The harness writes formulas of the old kind only for the step `legacy` and the cells a spill case lists in `legacy`. The measurement's Excel columns were computed again as dynamic formulas on 6 October (the former columns `excel-en-legacy.json` and `excel-ru-legacy.json` are in git at commit `85522cf`, under `docs/coverage-formulajs/`), and so were the sets `criteria`, `findate`, `stat`, `subtotal` and the probes (one answer of 5,824 changed). The LibreOffice column and the locale snapshot were made from books of the old kind.
- The size of an array taken from an argument (MUNIT, EXPAND, TAKE, DROP): only small number literals (at most 100) in the size position, no references, text or dates. `MUNIT(45688)` and `MUNIT("1.5")` in ru-RU (the text became the date 46143) ran Excel out of resources and raised a modal dialog. For the other size and count arguments (REPT, the order of BESSEL, periods, the days of WORKDAY) the "large" value is 1000, and a date and `"1.5"` are not put in.
- Excel computes in parts of up to 400 cases, by whole functions. Before and after each part System Events checks whether Excel has a window that is not a book window (subrole other than `AXStandardWindow`). If so, the run stops, the window's text and the part's number go to `meta.stopped` of the column's file, and nothing is clicked. If System Events answers the query with error -1719 (a book's window closed during it), the query is repeated, up to three times (`excelDialogs` in `excel.ts`, shared by all steps). The parts done stay in the file, and a new run goes on from the first part not done (`FCOV_FRESH=1` starts over).
- The interface language and the calculation locale come from launch arguments (`launchArgs` in `locales.ts`); Excel's settings (`defaults write`) are not changed. For en-US Excel is started with `open -a "Microsoft Excel" --args -AppleLanguages '(en)' -AppleLocale en_US`, for ru-RU without arguments (the system's Russian language and locale), for another tag with its language and region in the same form. It is restarted only with no books open: `quit`, waiting for it to exit, `open -a`. AppleEvents go only to a running Excel: `tell application "Microsoft Excel"` starts a stopped Excel without arguments. The empty new book Excel opens when started ("Book1" with the English interface, "Книга1" with the Russian one; no file, no edits) is closed without saving before the first part, so neither the book count nor the window check trips on it. The step `all` ends with ru-RU, so Excel is left running without arguments.
- The interface language changes computation, not only display, so en-US needs the English interface as well as the locale. With the Russian interface the text `"TRUE"` is no boolean (`IF("TRUE",1,2)` is `#VALUE!`, while `IF("ИСТИНА",1,2)` is 1), a boolean in text comes out as `ИСТИНА` (`TRUE&""`), and `CODE("Ж")` takes the Mac Cyrillic encoding (134 against 95). The first en-US column was computed with the en_US locale and the Russian interface and differed from the right one in 32 cases; it is in git (`docs/coverage-formulajs/excel-en-ru-ui.json` at commit `85522cf`), and the report keeps its comparison with the current one as fixed text. Excel shows error texts in the interface language; the measurement does not read them, the error code comes from `ERROR.TYPE`.
- Excel's answer does not always repeat. `VLOOKUP(5,D!L1:N6,D!E2:E4,FALSE)` (a column number from a range holding the formula `1/0`) gave `#REF!` or `#VALUE!` in one book depending on the row and the run, which looks like the recalculation order. `DAY(WEEKNUM(40977,1E+3)<>2.5)` gave 1 twice in the random check's book, and `#NUM!` once and in a small book. Check a difference on a case that touches such places by a second run and a separate book first.
- If Excel shows a dialog, hangs or asks for a manual action: stop and report it; do not close or get around the dialog.
- An Excel can come up answering `#NAME?` for the newer functions (`XLOOKUP`, `SORTBY`, `ARRAYTOTEXT`, `WRAPROWS`), in every book and every step, while the older ones compute (8 October, an instance another run had started); quitting it with no books open and starting it again cured it. A run whose newer functions all come back `#NAME?` is checked on a set with stored answers (`FCOV_FRESH=1` on a copy) before its answers are kept.
- Moving (cut and paste) a cell with a dynamic array formula to another sheet crashed Excel 16.113 twice (6 October, the struct set `spill`); Excel restarted by itself without arguments, that is in ru-RU, with a book recovery window, and the run stopped on that window. Do not add such a case.
- A window can open on another Space (a macOS desktop), where System Events lists none of Excel's windows; Excel then neither opens books (`open workbook` gives nothing, `wb` stays undefined) nor quits (error -128). `activate` brings the window forward, and the repair window is declined as usual. A table named like a cell (`T2`) is one cause: Excel repairs the file.
- A formula set through AppleScript (`formula`, `formula2`) is cut to its first 255 characters without an error (`=1+…+123` of 256 characters computes `…+12`), so a typed formula longer than that does not measure Excel; Excel for Windows takes it whole.
- AppleScript variable names inside `tell application "Microsoft Excel"` must not match terms of Excel's dictionary: a variable `a1` there reads as the reference style constant `A1`, and `worksheet a1` gives "object does not exist". The same goes for `tab`: inside the block use `character id 9` instead. A variable `kind` there takes its value without an error and keeps none.
- `special cells` finds nothing on a sheet that is not active ("the object you are trying to access does not exist"), and over a used range of one cell it looks at the whole used range: the parts step activates each sheet and asks over `A1:XFD1048576`.
- A hyperlink made with both `address` and `sub address`, or given its sub address after its address, loses the address: the parts step makes it with its sub address and sets the address after. An address with `#` is split there into the two.
